# 内容管理功能实现计划

## Context（背景）

当前博客应用底部 tabs 只有"首页"和"我的"两项。用户要求在底部 tabs 中间增加一个"内容管理"tab，并编写内容管理页面，支持对**自己发布的内容**进行增删改查（CRUD）。内容有三种类型：
- **文章**：富文本输入，可插入图片和音视频
- **短消息**：文字 + 配图，限制 200 字符
- **投票**：富文本输入，限制 500 字符

已澄清的关键决策（不再询问）：
- 富文本用 uni-app 原生 `<editor>` 组件（H5+小程序+App 跨端；支持 `insertImage` 插图；editor 不支持插入音视频，用独立 `medias` 字段补充）
- 媒体：本地选择（`uni.chooseImage`/`uni.chooseVideo`）+ mock 上传返回临时路径
- 数据：mock 内存数组（与 feed.ts/comment.ts 一致），API 层留 TODO 真实接口注释
- CRUD 范围：仅自己发布的内容（列表只列自己的）

**投票选项决策**：用户字面只提"富文本 500 字符"，但"投票"语义上必须有可选项；项目 `feed.ts` 的 `PollItem` 已建立"投票=问题+options"约定。故沿用此约定：投票 = 富文本问题（500 字限）+ 选项编辑器（动态增删，≥2 项）。如用户审阅时认为不需要选项，可去除该子组件。

预期结果：新增一个 tab 页 + 编辑器页 + mock CRUD API，与现有 detail/comment 功能并存，不改动 feed.ts。

## 实现要点

### 1. `src/api/content.ts` — 数据模型与 mock CRUD

类型：
- `ContentType = 'article' | 'message' | 'poll'`（与 feed.ts 的 FeedType 字面量一致，但不共享类型）
- `MediaItem { id, type:'image'|'video'|'audio', url, thumbUrl? }`
- `PollOptionInput { id, text }`（草稿态无 votes）
- `BaseContentItem { id, type, authorId(=0 自己), createdAt, updatedAt, status:'draft'|'published' }`
- `ArticleContent extends Base { type:'article', title, body(HTML), medias[] }`
- `MessageContent extends Base { type:'message', body(≤200纯文本), medias[] }`
- `PollContent extends Base { type:'poll', body(富文本问题≤500纯文本长度), pollOptions[] }`
- `ContentItem = ArticleContent | MessageContent | PollContent`
- `CreateContentInput` = Omit 各类型去掉 id/authorId/createdAt/updatedAt

API 函数（mock 内存数组 + setTimeout + TODO 注释）：
- `fetchMyContent(): Promise<ContentItem[]>`（按 updatedAt 倒序）
- `getContentById(id): Promise<ContentItem | null>`
- `createContent(input): Promise<ContentItem>`（idSeed 自增，push，markDirty）
- `updateContent(id, input): Promise<ContentItem>`（findIndex 合并，updatedAt 刷新，markDirty）
- `deleteContent(id): Promise<void>`（splice，markDirty）
- `uploadMedia(file): Promise<MediaItem>`（mock 回传临时路径）
- 模块级 `myContentDirty` 标志 + `markMyContentDirty()`：编辑页保存/删除后置 true，列表页 `onShow` 检测后拉取并复位（避免每次 onShow 无谓请求）

预置 mock 样本：article/message/poll 各 1 条，体现三类型。

### 2. `src/utils/content-logic.ts` — 纯逻辑函数

抽离自 editor.vue 便于单测。不依赖 DOM（小程序无 DOM API），用正则：
- `htmlToPlainText(html)`：去 `<[^>]+>` + 解码 `&nbsp;/&amp;/&lt;/&gt;/&quot;` + 折叠空白
- `charCount(html)`：`htmlToPlainText(html).length`
- `validatePollOptions(options)`：返回 `{valid, reason?:'empty'|'too-few'|'duplicate', emptyIndex?, duplicateText?}`（≥2 项、非空、去重）
- `validateMessageBody(text)`：`{valid, overflow}`（≤200）
- `mediaTypeLabel(type)`：图片/视频/音频
- `contentTypeLabel(type)`：文章/短消息/投票
- `summarize(html, max=60)`：纯文本截断 + 省略号

### 3. `src/pages/content/content.vue` — 列表页

Template：
- `.topbar`（fixed，无 back-btn，tab 页）+ `.topbar-title` "内容管理" + 右侧 `.new-btn`（品牌渐变背景 + `.ic-plus` 横竖两条纯 CSS）
- `.content`（paddingTop: 88px）：loading-state / empty-state（"还没有发布过内容"）/ `.content-list`
- `.content-card`（v-for）：类型徽章 `.card-type-badge`（article 紫渐变 / message 蓝紫 / poll 粉金）+ `.card-title`/`.card-excerpt`(summarize) + `.card-meta`(formatTime 复用 detail-logic + status 徽章 + `.edit-btn`/`.delete-btn`)
- `<CustomTabBar current="/pages/content/content" />`

Script：
- `onMounted` 拉取；`onShow` 检测 dirty 刷新
- `onEdit(item)` → `navigateTo editor?id=X&type=Y`
- `onNew()` → `navigateTo editor?type=article`
- `onDelete(item)` → `uni.showModal`（`confirmColor:'#ff5c9d'` 品牌粉危险色）确认 → `deleteContent` → toast → loadList

双 style 块（全局 page 背景 + scoped 主体）。

### 4. `src/pages/content/editor.vue` — 编辑器页（最复杂）

Template：
- `.topbar` + `.back-btn`（返回箭头）+ `.topbar-title`（新建/编辑）+ 右上 `.save-btn`（品牌渐变，disabled opacity:0.5）
- `.type-selector`（三段式 segmented：文章/短消息/投票；编辑模式全部 disabled 禁切换）
- **article 分支**：`.title-input` + `.rich-toolbar`（B/I/U/image 四按钮）+ `<editor id="artEditor" @ready @input>` + `.media-section`（音视频附件网格：图片/视频/音频 add 按钮）
- **message 分支**：`<textarea maxlength="200" v-model="form.body">` + `.char-counter`（N/200，满 200 变 #ff5c9d）+ `.media-grid`（仅图片）
- **poll 分支**：`.rich-toolbar` + `<editor id="pollEditor" @ready @input>`（问题富文本）+ `.char-counter`（charCount/500，超限红 + 阻断保存）+ `.options-editor`（v-for option-row：序号+input+opt-remove（≥3才显示）；`.opt-add` 添加）

Script 关键：
- `onLoad(options)`：读 type/id；id 存在则 isEdit + loadExisting（editor setContents 需等 @ready，用 nextTick 兜底）
- `onEditorReady`：`editorCtx = uni.createEditorContext('artEditor', getCurrentInstance().proxy)`；编辑态 setContents
- `format(name)`：`editorCtx.format('bold'|'italic'|'underline')`
- `insertImage()`：`uni.chooseImage` → `uploadMedia` → `editorCtx.insertImage({src, width:'100%'})`
- 字数限制策略：editor 不支持 maxlength；`@input` 实时 charCount，超 500 toast 软提示 + 计数器变红；保存时硬校验阻断。**不做 setContents 截断**（会丢光标+破坏 HTML）
- `chooseMedia(t)`：image→chooseImage；video→chooseVideo；audio→chooseMessageFile（小程序/H5）
- 选项：`addOption`/`removeOption`（≤2 时 toast 提示）
- `onSave()`：分支校验（article 标题必填 / message ≤200 / poll ≤500 且 options 校验）→ create/update → toast → `navigateBack`
- 保存后刷新机制：模块级 dirty 标志 + 列表页 onShow（非 eventChannel，代码侵入小、跨端一致）

editor API 兼容性：`createEditorContext`/`setContents`/`getContents`/`insertImage`/`format`/`@ready`/`@input` 在 H5+小程序+App 三端均支持；App nvue 不支持（pages.json 默认 vue 页面无需处理）。

### 5. `src/components/CustomTabBar.vue` — 中间图标

tabs 数组中间插入：`{ path:'/pages/content/content', label:'管理', icon:'content' }`（label "管理"2字与首页/我的平衡）。

ic-content 纯 CSS 图标（文档+笔，40×40rpx 容器，#ccc 默认，active #7b5cff）：
- `.ct-doc`：border 矩形（文档主体）
- `.ct-line-1/.ct-line-2`：background 短线（模拟文字）
- `.ct-pencil`：rotate(45°) 矩形（笔杆）
- `.ct-tip`：border-top 三角（笔尖）
- active 态：doc 切 border-color；line/pencil 切 background；tip 切 border-top-color

### 6. `src/pages.json` — 路由

新增两条（detail 之后）：
- `pages/content/content`（custom navigationStyle，navigationBarTitleText "内容管理"）
- `pages/content/editor`（custom navigationStyle，navigationBarTitleText "编辑"，不开 enablePullDownRefresh）
